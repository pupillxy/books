# 番茄小说接口开发文档

> 生成日期：2026-09-26
> 参考源码：`_reference/fanqie-rank-mcp`（Python，直连番茄）、`_reference/mcp-server-fanqie`（TypeScript，中转外壳）
> 用途：自建后端中转番茄数据 + Flutter 客户端（Android / iOS 优先）

---

## 0. 一句话结论

**能自己掌控的路线是"网页端直连"（fanqie-rank-mcp 路线）**：用 `fanqienovel.com` 网页端接口 + `a_bogus` 签名 + PUA 字体解密，可覆盖榜单、分类、书籍详情、目录、章节正文。设备注册/设备池那套只存在于闭源中转服务里，**不要依赖**。

---

## 1. 三条数据源路线对比

| 路线 | 原理 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|
| A. 网页端直连 | 请求 `fanqienovel.com`，带 `a_bogus` 签名，PUA 解密 | 完全自控、实现开源可抄、无需设备注册、搜索接口无需签名（§3.6） | 部分内容仅限免费章节 | **主路线** |
| B. 第三方中转 | mcp-server-fanqie → `http://101.35.133.34:5000` | 接口全（搜索/正文/听书/漫画） | 闭源黑盒、IP 裸奔、随时跑路、隐私风险 | 仅当临时调试工具 |
| C. App 端直连 | 逆向 `fqnovel.com` App 接口 + 设备池 | 数据最全 | 需设备注册+签名逆向，门槛极高 | 不做 |

---

## 2. 系统架构

```
Flutter App (Android/iOS)
        │  HTTPS + JWT
        ▼
自建后端（书城 API）
   ├─ 书源抽象层 ── 番茄网页端直连（a_bogus + PUA 解密）   ← 本文档重点
   ├─ 缓存层（Redis/内存：榜单、书籍详情、目录缓存）
   ├─ 用户系统（书架/阅读进度/偏好，参考 music-server 的设计）
   └─ 推荐服务（榜单 + 分类 + 标签的规则推荐，番茄个性化推荐流不可用）
        ▼
fanqienovel.com
```

**为什么必须走后端中转**：a_bogus 签名依赖 UA 一致性、PUA 解密表需要更新维护、网页端点有 Cookie 需求——这些放在客户端无法热更新，App 一旦发版就锁死了。

## 3. 网页端直连接口清单（主路线）

来源：`_reference/fanqie-rank-mcp/api.py`。域名全部为 `fanqienovel.com`。

### 3.0 公共约定

| 项 | 值 |
|---|---|
| 文本类响应 | **全部需过 PUA 解密**（见 §5），包括书名/作者/简介/正文 |
| User-Agent | 榜单 JSON 接口用安卓客户端 UA，网页页面用 Chrome UA，**UA 必须与 a_bogus 签名输入一致** |
| 重试 | 指数退避，3 次（api.py:42-80） |

安卓伪装 UA（api.py:20-28）：
```
Dalvik/2.1.0 (Linux; U; Android 10; SM-G975F Build/QP1A) com.ss.android.article.news/831
```

### 3.1 榜单分类列表

- **URL**：`GET https://fanqienovel.com/rank`（HTML 页面）
- **UA**：Chrome 网页 UA
- **解析**：正则提取 `arco-menu-inner` 菜单容器，按 `arco-menu-inline-header` 分组，取 `<a href="/rank/{id}">名称</a>` 得到 id/name（api.py:183-208）
- **兜底**（接口失败时硬编码，api.py:211-230）：

| ranking_id | 分类 |
|---|---|
| 1_2_1141 | 男频·阅读榜·西方奇幻 |
| 1_2_1142 | 男频·阅读榜·玄幻仙侠 |
| 1_2_1143 | 男频·阅读榜·都市生活 |
| 1_2_1144 | 男频·阅读榜·历史架空 |
| 0_2_1139 | 女频·阅读榜·古风世情 |
| 0_2_1140 | 女频·阅读榜·现代言情 |

- **ID 格式**：`{gender}_{rankMold}_{categoryId}`，gender：1=男频 0=女频；rankMold：1=新书榜 2=阅读榜
- **常用 categoryId**：玄幻脑洞 257、传统玄幻 258、都市脑洞 262、东方仙侠 1140、科幻末世 8、都市修真 124、西方奇幻 1141、都市高武 1014

### 3.2 榜单书籍列表 ★核心接口

- **URL**：`GET https://fanqienovel.com/api/rank/category/list?{query}&a_bogus={签名}`
- **query 按序拼接**（api.py:252-257）：
  ```
  app_id=2503&rank_list_type=3&offset={offset}&limit={limit}&category_id={category_id}&rank_version=&gender={gender}&rankMold={rank_mold}
  ```
- **UA**：安卓客户端 UA（§3.0），签名用同一 UA 生成
- **响应**：`data.book_list[]`，字段名有多套兼容命名，全部需 PUA 解密：
  - 书籍 ID：`book_id` / `bookId`
  - 书名：`bookName` / `book_name`
  - 作者：`author` / `author_name`
  - 简介：`abstract` / `description`
  - 封面：`thumbUri` / `thumb_url` / `thumbUrl` / `cover` / `cover_url` / `img_url`（形如 `https://p3-novel.byteimg.com/...`）
- **代码**：`fetch_ranking_books` api.py:233-288

### 3.3 书籍详情

- **URL**：`GET https://fanqienovel.com/page/{book_id}`（HTML 页面，无签名）
- **UA**：Chrome 网页 UA
- **解析**：HTML 内嵌 `window.__INITIAL_STATE__` JSON → `bookInfo.description` 等路径取简介；章节链接正则 `<a href="/reader/(\d+)">` 抓取
- **返回**：简介 + `chapters[{id, index, title, is_free}]`
- **代码**：`fetch_book_page_detail` api.py:294-341（`__INITIAL_STATE__` 提取器 api.py:86-136）

### 3.4 章节目录（JSON API，代码里有但未挂 MCP 工具）

- **URL**：`GET https://fanqienovel.com/api/reader/directory/detail?bookId={book_id}`
- **UA**：Chrome 网页 UA + 可选 Cookie
- **响应**：`data.chapterListWithVolume`（或 `list` / `item_list`，多套命名兼容，可能嵌套卷），章节字段：`itemId` / `item_id`、`title` / `chapterName`、`needPay`、`isPaidStory`
- **免费判定**：`is_free = (needPay == 0) && !isPaidStory`
- **代码**：`fetch_chapters` api.py:344-394

### 3.5 章节正文

- **URL**：`GET https://fanqienovel.com/reader/{chapter_id}`（HTML 页面）
- **UA**：Chrome 网页 UA + 可选 Cookie
- **解析**：`__INITIAL_STATE__.reader.chapterData` → `title`、`content`（HTML），去标签、还原 `&nbsp;` 等实体、PUA 解密
- **限制**：网页端点只能读**免费章节**；付费章节需 Cookie（登录态）且仍有壁垒
- **代码**：`fetch_chapter_content` api.py:397-427

### 3.6 搜索 ★已验证可用（2026-09-28 实测）

网页端自带搜索接口，**无需 a_bogus 签名、无需 Cookie、不走 PUA 加密**，全部字段明文返回。

- **URL**：`POST https://fanqienovel.com/api/author/search/search_book/v1?{query}`
- **方法必须是 POST**：同样参数用 GET 会返回 `HTTP 200` 但**响应体为 0 字节**（最大的坑，社区资料多误写为 GET）
- **请求头**：Chrome 网页 UA 即可，无需 Referer / Cookie / 签名（前端 JS bundle 里也无 a_bogus/msToken 注入）
- **query 参数**（按序）：
  ```
  filter=127,127,127,127&page_count=10&page_index=0&query_type=0&query_word={关键词}
  ```
  - `filter` 必填，留空返回 `code: -2`；四段 127 = 全频道（前端默认值）
  - `page_index` 从 0 开始；`page_count` 每页条数
  - `query_type`：0 = 综合（书名+作者）
- **响应**：`code=0`，`data.search_book_data_list[]` + `data.total_count`（实测"剑来" total=300，翻页正常）：
  - `book_id`、`book_name`、`author`、`book_abstract`（简介明文）
  - `category`（逗号分隔分类）、`creation_status`（0/1，含义未验证）
  - `first_chapter_id` / `last_chapter_id` / `last_chapter_title` / `last_chapter_time`（unix 秒）
  - `thumb_url`（封面直链 `p3-reading-sign.fqnovelpic.com`，带签名参数）+ `thumb_uri`
  - `read_count`、`word_count`
- **前端佐证**：搜索页路由 `/search/:query`（直连需 URL 编码，裸中文 404）；`Search.7fef57d7.js` 拼参与上完全一致
- **后续实现**：server 端 `GetSearch(keyword, offset, limit)` 即可，注意 filter 常量与 POST 方法

### 3.7 App「推荐榜」的网页端替代（2026-09-28 实测）

App 首页的推荐榜卡片（推荐/完本/巅峰/新书/短剧）走 App 端接口，网页 `/rank` 菜单只有"阅读榜/新书榜 × 分类"。实测网页榜单 API（§3.2）扫描 `rank_list_type 1-5 × rankMold 0-5 × category_id {0,'',738,-1}` 共 30+ 组合：**必须有真实 category_id，无全分类形态**（category_id=0 等均返回 code=0 空列表）。

替代方案：用书库 API（§中 GetLibraryBooks，`/api/author/library/book_list/v0/`）拼伪榜单，已实测出数据：

| App 榜 | 网页端近似 | 参数 |
|---|---|---|
| 推荐榜 | 书库热门序 | `category_id=-1&creation_status=-1&word_count=0&sort=0`（分 gender） |
| 完本榜 | 全分类完结热门 | 同上 + `creation_status=0` |
| 新书榜 | 现有 rank API 新书榜 | `rankMold=1`（分类维度）或书库 `sort=1` |
| 巅峰榜 | 长篇热门 | 书库 `word_count=5`（200万+）+ `sort=0` |
| 短剧榜 | 不适用 | 红果源已有目录 |

注意：书库 API 的 PUA 用 `libpua.go`/`lib_map.json` 那套映射（与榜单映射不同）；`creation_status` 0=完结 1=连载。书库热门序 ≠ App 推荐榜（后者含运营/个性化权重），个人自用足够。如需与 App 完全一致，走真机抓包拿 App 榜单接口参数（见 §1 路线 C 讨论）。

> **已实现（2026-09-28）**：`GET /api/store/featured`（榜单清单）、`GET /api/store/featured/{recommend|finished|new|peak}?gender=1&offset=0&limit=10`（榜单内容），见 `handler/store.go` FeaturedBoards/FeaturedBooks；UI 原型 `docs/mockups/store_featured.html`。

## 4. a_bogus 签名（重点）

来源：`_reference/fanqie-rank-mcp/a_bogus.py`，移植自字节系通用反爬签名（参考项目 tomato-rank-download 的 Rust 实现）。

### 4.1 使用方式

- 以 **query 参数** 附在 URL 尾部：`...&a_bogus={值}`（非请求头）
- **输入两项**（a_bogus.py:441-457）：① 查询参数字符串（不含 `?`）；② 本次请求的 User-Agent
- **签名与 UA 强绑定**：两者任一与实际请求不一致即失效

### 4.2 算法流程（自底向上）

1. **SM3 国密哈希**纯实现（a_bogus.py:128-241），写入前做自定义 URL 编码
2. URL 参数：SM3 → hex → 再 SM3 双重哈希，取第 22/23 字节；固定串 `"cus"` 同样处理；UA 先 RC4（密钥 `0x01,0x00,0x0E`）→ 自定义 Base64 表 `s3` → SM3，取第 24/25 字节
3. 拼装字节数组：时间戳（start/end 毫秒）+ 环境指纹串 `1536|747|...|Win32` + `page_id=6241` + `aid=6383`，算 XOR 校验和（a_bogus.py:329-417）
4. 整体 RC4 加密（密钥 `[121]`），前置 12 字节随机数，用自定义 Base64 表 `s4`（`Dkdpgh4ZKsQB80/...`）编码，末尾补 `=`

### 4.3 后端移植建议

| 后端语言 | 建议 |
|---|---|
| Python | 直接抄 a_bogus.py，零成本 |
| Node.js | 找现成 `a_bogus` npm 包，或按源码逐函数移植（SM3 有成熟库） |
| Java/Kotlin | 搜开源 a_bogus/SM3 实现，对照移植 |
| Rust | 直接看上游 tomato-rank-download 的实现 |

**验证方法**：移植后先用固定参数对比 Python 版输出是否一致，再实测榜单接口返回 `code: 0`。

## 5. PUA 字体解密（重点）

番茄对**所有文本字段**做了字体级字符替换：把真实字符映射到 Unicode 私有区 `U+E3E8` 起（码点 58344–58715），再用自定义字体渲染。直接显示就是乱码。

- **解密表**：`_reference/fanqie-rank-mcp/pua_map.py` 的 `PUA_MAP` 字典，码点 → 真实字符，覆盖 0-9、a-z、A-Z 及约 300 个高频汉字（"的一是了我不人在他有这…"）
- **解密函数**：`decrypt_pua()`（pua_map.py:99-108）——逐字符查表，未命中保留原字符
- **另一份等价实现**：`_reference/mcp-server-fanqie/src/fontDecrypt.ts`（换算公式 `gid = 58344 + (codePoint - 0xE3E8)`，fontDecrypt.ts:91-110，来源 CSDN 文章）
- **风险**：静态映射表，番茄更换加密字体即失效，需保留重新生成映射的能力（对比新字体文件的字形）

**正文额外处理**：去 `<p>`/`<br>` 标签、解码 `&nbsp;` 等 HTML 实体（fontDecrypt.ts:154-176）。

## 7. Flutter 客户端架构建议（Android/iOS 优先）

### 7.1 项目分层

```
lib/
├── core/            # 网络客户端(dio)、主题、路由、常量
├── data/
│   ├── api/         # 后端 API 封装（唯一数据出口，不直连番茄）
│   ├── models/      # Book / Chapter / RankCategory 等（json_serializable）
│   └── repositories/# 仓库层：书城/书架/阅读器
├── domain/          # （可选）实体与用例
└── presentation/    # 页面
    ├── home/        # 书城：榜单/分类/推荐（对应 §3.1-3.2）
    ├── search/
    ├── book_detail/ # 详情+目录（对应 §3.3-3.4）
    ├── reader/      # 阅读器（对应 §3.5，分页排版自行实现）
    └── bookshelf/   # 书架（本地持久化 + 服务端同步）
```

### 7.2 技术选型建议

| 项 | 建议 | 说明 |
|---|---|---|
| 状态管理 | Riverpod | 书城多数据源组合场景比 Bloc 轻 |
| 网络 | dio + 拦截器 | 统一加 JWT、错误码处理、日志 |
| 本地存储 | drift（数据库）+ shared_preferences | 阅读进度、缓存章节 |
| 阅读器 | 自绘（CustomPainter / Flutter 原生排版） | 分页、翻页动画是核心体验，不建议 WebView |

### 7.3 关键设计点

1. **客户端永远不碰番茄**：所有番茄相关逻辑（签名、解密、UA）锁死在服务端。客户端只有一套干净的书城 API。
2. **章节缓存策略**：正文接口走 HTML 解析较慢，客户端按章缓存（drift），服务端也缓存一层。
3. **书架同步**：参考你 music-server 的做法——阅读进度/书架存服务端，跨设备同步。
4. **图片**：封面域名 `p3-novel.byteimg.com` 可直连，但建议后端做一层图片代理/缓存，防防盗链策略变化。
5. **降级设计**：书源抽象成接口（`NovelSource`），番茄只是实现之一，将来可插其他源（起点/七猫网页端等）。
